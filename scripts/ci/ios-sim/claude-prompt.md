# Device test session: SimpleX Chat iOS, online search

You are testing the SimpleX Chat iOS app in an iPhone 17 simulator (iOS 26.5, screen 402 x 874 points) on a GitHub Actions runner. The feature under test is online search: from the chat list and from New chat, the app sends the search text to a SimpleX Directory and shows its listed groups and channels. You run the cases of the device test plan (at the end of this prompt) that the section "This session" names, in the layout it names, and write a report. You cannot change the app or the runner; anything wrong you find is a finding for the report.

## Tools

- **Bash runs only the `ui` helper**, one command per call: `ui tap "Create profile"`, `ui find Settings`. Any other program, a pipe, a redirection, `;` or `&&` is denied. Its commands are listed under "The ui commands" below.
- **Read, Write and Edit work only in the current directory.** Screenshots go to `shots/` (look at the `-view.jpg` files, they are smaller), and you write `report.md` here. This whole prompt, with the plan, is also `prompt.md` here: read it again when you are unsure, and after the conversation has been compacted.

## What you need to know about the app and the helper

- **Layouts.** With the one-hand UI (reachable toolbar, the default) the chat list is drawn from the bottom up: the toolbar (your profile image and the "Compose" pencil) is at the bottom, the search field just above it (y about 754), the list tags ("Add list" when there are no lists) or the online search rows above the field, and chats and results stack upwards from there. With the top bar the toolbar and the search field are at the top, the tags above the field, and "Search in Directory" and "Connect to …" appear below it. A profile without conversations sees onboarding pages ("Talk to someone") in place of the list, with the search field above them. Stay in the layout the session names; the app starts in it, and `ui relaunch` keeps it.
- **Positions.** "Above" means a smaller y. Judge order and position from the tree's coordinates, and look at a screenshot when you judge layout (truncation, overlap, images).
- **The search field** has no label; tap it with `ui tap-value "Search or paste SimpleX link"` when empty, or by its text. To clear it, tap the field so it is focused, then "Cancel" next to it ("Cancel" exists only while the field is focused; it also hides the keyboard); tapping the "Close" image inside the field did not clear it in an earlier run. Type text as one quoted argument (`ui type "ci seed"`). The keyboard capitalizes the first letter and autocorrects words (an earlier run saw "ci" become "Ci" and a typed name become another word when a button was tapped), so check the field's value in the tree after typing, and before typing check that the field shows its placeholder. The keyboard's Search key is `ui key return`; the keyboard's keys are below the screen and not listed in the tree, and the screenshots do not show the keyboard.
- **Pasting** (C4, W3): `ui clipboard "<link>"` with the link given under "This session", tap the empty field once to focus it and once more to open its menu, then tap its "Paste" item (two elements carry that label: use `ui tap-xy` on the one `ui find Paste` shows in the menu).
- **Directory search.** "Search in Directory" (a row) and the keyboard's Search key search the directory, and only the directory: no SimpleX name is resolved by a search, and "Connect to …" stays shown next to the results. While the switch Settings → Privacy → "Directory search" is off (the default), every search first asks "Enable Directory search?" with "Cancel" and "Enable"; Enable turns the switch on and searches, and later searches don't ask. "Search in Directory" is hidden while results for the current text load or show. Results come as one list without headers: your chats first, then per result an avatar image, `"#name"`, the description, "N members" or "N subscriber(s)", and "Open", as separate texts. An entry you already have that the screen doesn't already list is shown instead as that chat's row, with no `#` and no "Open": on the chat list the same row as your other chats (name, last message, time), in New chat a row like a contact's. When every result of the last page loaded is a chat already listed, the list shows "All results on this page are already in your chats". The last row is the load row, "Load more · N left" (or "Load more" when the directory sends no count); a failed search or page shows "Search failed, tap to retry". These two are buttons with an icon, so their label in the tree may start with the icon's name: find them with `ui find` and tap with `ui tap-xy` when `ui tap` with the text alone finds nothing. A search takes 1–2 s here (it sets up an encrypted connection) and times out after 10 s. A channel's row shows the subscriber count the directory publishes for it (`publicMemberCount`), not the listings' members column, which counts every member record (owner, relay, directory), so the two differ by design.
- **Order with the one-hand UI.** Results read from the bottom like the chats: your chats nearest the search field, then the results, each "Load more" adding its page above the earlier ones, and the load row at the top of the results, farthest from the field. With the top bar the order runs downwards from the field, the load row last.
- **Long press** (`ui long-press <x> <y>` at a result's centre): on a result row it opens a menu with one item, "Open", over a lifted copy of the row without its "Open". Close the menu by tapping outside it (for example `ui tap-xy 200 100`), not by choosing Open, unless the case says so.
- **Disabled elements** end with "disabled" in the tree.
- **Holding a search open.** A search answers in 1–2 s here, too fast to see its loading state. For the cases about a search in progress (D1, D11, D12, W9, G3, and "Load more" while loading in D6), stop the directory first (`ui directory stop`): the search then waits 10 s before it fails. Start it again afterwards. The 10 s count from the search's start, and each of your turns takes several seconds, so do the case's action (for G3, `ui tap Compose`) as the very next command after starting the search, without a shot in between; an action after the search has failed tests nothing.
- **Ambiguous labels.** When `ui tap` says several elements match a label (seen for "Paste", "Channels", "Account"), tap the one you mean with `ui tap-xy` at its centre, taken from `ui find`.
- **Hidden elements.** The tree always contains the closed user picker: the profile name, "Create SimpleX address", "Chat preferences", "Your chat profiles", "Use from desktop", "Settings", at coordinates on the screen even while it is hidden. Do not tap them unless you opened the picker by tapping your profile image in the toolbar (`Image "Account"`, 32 x 32; tap its centre with `ui tap-xy`).
- **Settings → Privacy → "Directory search"** (C5–C7): open the picker, "Settings", "Privacy", the "Directory search" switch in the Chats section. Go back with the navigation back buttons and close Settings by swiping it down.
- **New chat** is the "Compose" button (the pencil) in the toolbar. With the top bar the toolbar is hidden while the search field is focused; tapping the "Search in Directory" row hides the keyboard, and the pencil shows again while that search runs.
- **Counting requests.** `ui requests` tells how many directory searches the app sent; compare before and after an action to prove that something was or was not sent (C6, C9, D11, D12).
- **Joining** (the app's normal flow, from `NewChatView.swift`; an earlier session took its first step for a failure). Tapping a result or its "Open" shows "Loading profile…" in the field, then opens the group or channel, not yet joined, with no alert: "Tap Join channel" in it and a "Join channel" / "Join group" bar at the bottom; tapping that bar joins (a channel then shows "you are subscriber"; a group may stay "connecting"). Opening a group or channel from a link instead shows an alert first, with its name (and subscriber count for a channel) and "Cancel" / "Open channel" or "Open group": that is the start of joining, not a sign that the entry is known. An entry already opened, joined or connecting shows the same kind of alert, plus your role ("You are a subscriber", "You are a member") once joined. So each case that opens or joins uses the entry named for it under "This session", which no earlier case has touched. Opened and joined chats appear in the chat list, and the profile is no longer "without conversations".
- **A second profile** (D13, and D14 once the first profile has chats): open the picker, "Your chat profiles", add a profile; a new profile has no conversations. Switch back to the first profile when done.
- **Text size** (D3): `ui text-size accessibility-large`, and back to `ui text-size medium` afterwards. Only one phone size is available.
- **If the app gets stuck**, `ui relaunch` restarts it (search text and results are cleared, everything else stays).
- Waiting: prefer `ui wait <text> <secs>` over repeated trees; `ui wait` returns at once when the text is already shown.

## The test backend

When "This session" gives the test directory's address, the runner also runs a test backend: a chat relay, a SimpleX Directory with the groups and channels listed under "Test directory" below, a server that resolves SimpleX names, and contacts that accept connections. `ui directory stop|start` stops and starts the directory (after `ui directory start`, wait about 15 s before using it), and `ui listings` prints what it lists. Stop the directory instead of turning networking off (D7, D8; the simulator shares the runner's network): while it is stopped, searches fail after 10 s.

**SimpleX names**: a search never resolves names; only "Connect to …" does (C3, C11, W2, G5). The names server's address is under "This session"; the names it knows are under "Test directory" → "SimpleX names" (all end in `.testing`; a bare word of 5 or more letters is completed with `.testing`, so `cinews` is `cinews.testing`). Set the app up for it once, before the first case that taps "Connect to …" (if an earlier session in this run did it, check it instead: the server is listed under "Your servers" and "To resolve names" is "yes" on it; finish step 4 on that server if not, rather than adding it again, as a second copy of an address is an error):

1. Open the picker (your profile image), "Settings", "Network & servers".
2. Under "Preset servers", open each operator ("SimpleX Chat", "Flux"), turn "To resolve names" off, and go back. Otherwise the app may ask the real servers, which do not know the test names.
3. "Your servers" → "Add server" → "Enter server manually". Put the names server's address in the address field by pasting it (`ui clipboard "<address>"`, tap the field twice, tap the menu's "Paste"; typing it would let the keyboard capitalize it), check it in the tree, and go back.
4. In "Your servers", open the new server and turn "Use for new connections" on: only then does the server show its pickers "To receive", "For private routing" and "To resolve names". Set them to "no", "no" and "yes", then go back.
5. On "Network & servers", tap "Save servers" (and "Save" if asked). Close Settings.
6. Check: type `cinews` and tap "Connect to cinews.testing": the alert for the channel cinews must appear (Cancel it). If it does not, record what you see and look at the steps again before running the cases that connect by name.

**What the names are for:** `cinews` is a listed channel (C11, G5); `cialice` and `cibobby` are contacts that accept a connection at once (G1, G5; `cibobby`'s profile is called "Robert", so its name is not in its display name); `ciboth` has both a contact address and a channel; `cinone` is not registered. Which case uses which contact in this layout is under "This session".
