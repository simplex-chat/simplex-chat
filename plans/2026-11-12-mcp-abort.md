# SimpleX MCP server 0.3.0: /abort in status messages

Status: draft for review. Design of 2026-11-12; decisions 1 to 10 by the user. Code: stacked on the Claude Code activity (`plans/2026-11-11-mcp-live-activity.md`) at `53a7fb036`; app references at the same commit. Pending: section Open.

Dependencies:
1. The status message of `plans/2026-11-10-mcp-live-status.md`, with the waiting status of `plans/2026-11-11-mcp-live-activity.md`, decision 8.
2. A script that runs the agent, as in section Runner.

## Decisions

1. Option: the feature is turned on by `serve --abort-file FILE`; FILE lies in a folder disjoint from the data folder.
2. Without the option, the behavior is unchanged, and `/abort` is an ordinary message.
3. With the option, `/abort` is offered in each status line.
4. Senders: anyone who can post in a chat with a shown status message, groups included.
5. At a message `/abort`, exact after trimming, in a chat with a shown status message:
   - 1 is added to the count in FILE: one decimal line, written to `FILE.part` with mode 0644, which is renamed to FILE;
   - every status message of the server, in all chats, is ended with `◼ aborted`;
   - the message is marked read and never returned by `receive` or `send`;
   - the sender, folded to one line, and the chat are logged on one line.
6. `/abort` in a chat without a shown status message is an ordinary message.
7. At start, a missing FILE is written with 0; an existing count is kept.
8. Runner: as in section Runner.
9. Generic wording in code, tests, docs, plans and commit messages.
10. Source budget: about 70 changed lines in `src`, at most 84.
11. 2026-11-13: 1 is added to the count in memory only after FILE is written; a failed write leaves the count unchanged.
12. 2026-11-13: decisions 5 and 6 apply once per message, with the status shown at the first of its arrival and its read by a `receive`; the decision is kept, so an abort is never returned, and an ordinary `/abort` is never counted.

- `render` passes the offer to `statusText`: ` · /abort` when `Agent.abort` is set, `""` otherwise. `statusText` returns LINE + OFFER, or LINE + OFFER + "\n" + NOTE.

## Recognition

```
item          rule
place         AgentTools.decideAbort, once per item: in onNewItems at the newChatItems event, before the item watch,
              or in receive at its read of the unread items, whichever is first
chat          the main conversation (chatRef); support chats of members excluded
message       received (rcvMsgContent), not sent live (itemLive absent), not edited, type text, text.trim() equal to "/abort"
status        Statuses.offersAbort(chat) at that moment: Agent.abort set, and the chat's status with 1 or more renders
record        AgentTools.abortItems: item ID -> true for an abort, false for an ordinary /abort; a recorded item is not decided again
sender        any: a contact, or any member of a group or business chat
other items   as before: a status queued at a message received in an eligible chat; also at an ordinary /abort
returned      the items not recorded as aborts, delivered to the item watch
```

- `receive` decides the unread items it reads, then leaves out the aborts.
- The responses of `send` are collected from the item watch.

```mermaid
sequenceDiagram
  participant C as Core
  participant R as receive
  participant T as AgentTools
  C->>T: newChatItems [/abort], at the event
  R->>T: unread items [/abort], at a read
  Note over T: decideAbort at the first of the two; the other finds the record
  T->>T: abortItems[ID] = offersAbort(chat)
  alt true
    T->>T: the steps of section Abort; the item left out of the item watch and of receive
  else false
    T->>T: an ordinary message: delivered to the item watch, returned by receive
  end
```

## Abort

```
decideAbort(chat, chatInfo, chatItem):
  recorded in abortItems, sent live, edited, or not a received text "/abort": nothing
  abortItems[item ID] = offersAbort(chat); false: nothing more
  markRead(chat, [item ID]), not awaited; a failure: stderr "abort in CHAT: ERROR"
  stdout "Abort by SENDER in KIND NAME (CHAT)."
  Agent.abort(): the count + 1 written to FILE, then kept as the count
  Statuses.abort(): end(chat, "◼ aborted") for each status with 1 or more renders, end(chat, "") for one with 0
  a failure of the two steps above: stderr "abort in CHAT: ERROR"; the statuses kept
```

- SENDER: `from` of `toMessage`, folded by `oneLine`. KIND NAME: `subjectText` of `chatSubject` without the SimpleX name, folded by `oneLine`.
- `end(chat, text)`: parameter `text`, `""` by default. With `LiveMessage.end(text)`, a posted item is edited to `text`, not live, and nothing is sent for an item not posted (`packages/simplex-chat-nodejs/src/api.ts:1199-1213`).
- The endings are awaited at stop; the ended statuses are not counted as status deletions.
- After an abort, `/abort` is offered in no chat until a status is rendered again.
- At the start of a waiting `receive`, its chat's status is ended; an `/abort` there is then an ordinary message.

## Counter file

```
item     value
content  the count in decimal, then "\n"
write    FILE.part written with mode 0644; chmod 0644 except on Windows; FILE.part renamed to FILE
start    abortCounter(FILE) in startServer, after writeHeadersFile, before ChatApi.init:
         a first line matching ^\d{1,15}$ is the count, FILE unchanged;
         otherwise, a missing FILE included, "0\n" written, the count 0;
         a missing folder, a folder at FILE, or a refused write: the start fails, the lock released, exit code 1
abort    the count + 1 written, then kept in memory; a failed write leaves the count unchanged
writer   the server only
reader   the script that runs the agent: the first line
```

## Runner

```
step     the script that runs the agent
start    reads FILE's first line, a missing FILE counting as 0, then starts the agent
watch    reads FILE's first line about every second
change   stops the agent's process group, then starts the agent again
resume   may continue the agent's session with one prompt line saying that the owner aborted the last task
mounts   FILE's folder, read-only, where the script runs; not FILE; not the data folder
```

## Threat model

```
actor                                    capability                          mitigation
a member of a chat with a shown status   stops the agent's work in all chats  each abort logged with the sender and the chat; after it, /abort
                                                                              offered in no chat until the next render
a sender in a chat without a status      sends "/abort"                      an ordinary message
a sender in a support chat of members    sends "/abort"                      main conversation only
a sender                                 a display name with line breaks     folded to one line in the log
the agent                                posts "/abort"                      its items are sent items, never recognized
the agent or the script                  reads FILE                          FILE holds one number, in a folder disjoint from the data folder
the agent                                writes FILE                         FILE's folder mounted read-only where the script runs (deployment)
```
