# UI test catalogue 4: settings, database, migration, remote desktop, misc

Every settings and non-chat screen of the desktop app, mapped to UI test cases: **232 test cases** (**20** of them `@Ignore`) in 13 groups. One group is the remote-desktop flow, where a CLI plays the mobile as in `tests/RemoteTests.hs`. Rows follow `00-legend.md` (paths, `Test case(s)` format, Needs codes, users, ownership). None of these tests is written yet.

## Path prefixes, legend and harness facts

**Path prefixes** (repo-relative; `C/`, `D/`, `H/` as in `00-legend.md`):
- `US/` = `C/views/usersettings/`
- `NS/` = `US/networkAndServers/`
- `T/` = `tests/`

**Legend:**
- **Picker** means clicking your own avatar in the chat list top bar, which opens UserPicker (`C/views/chatlist/UserPicker.kt:46`).
- **Settings** means Picker > "Settings" (`UserPicker.kt:381`).
- **Pref**: see `00-legend.md`.
- **Log**: see `00-legend.md`.
- **Needs** codes are the shared set in `00-legend.md`.

**Harness facts that affect these tests:**
1. **File dialogs.** Complete `simplexWindowState.openDialog` / `saveDialog` / `openMultipleDialog` (`D/DesktopApp.kt:273-275`, awaited in `D/platform/Files.desktop.kt:68-101`).
2. **Esc.** The real handler is `Window(onKeyEvent)` (`DesktopApp.kt:125-130`), which isn't rendered in tests. For modals the harness's `escape()` runs the same `simplexWindowState.backstack` logic; alerts register no back handler, so a test closes an alert with `press(Key.Escape)` on the dialog root (plan §7.4).
3. **Settings storage.** Settings go to `<configPath>/settings.properties` (`D/platform/Resources.desktop.kt:39-40`). Theme overrides (wallpapers, colours, imported themes) go to `<configPath>/themes.yaml` (`C/platform/Files.kt:127-161`). `themes.properties` (`Resources.desktop.kt:41-42`) holds only the legacy `Themes` map.
   - On desktop the Cryptor is a passthrough (`D/platform/Cryptor.desktop.kt:3-10`), and `SharedPreference`-backed secrets are stored Base64-encoded (`C/views/helpers/DatabaseUtils.kt:29-32`). So `EncryptedAppPassphrase`, `EncryptedSelfDestructPassphrase` and `EncryptedDBPassphrase` hold the Base64 of the plain value; tests decode and compare.
4. **Fresh state per test.** Each test starts with a fresh database, default prefs plus the harness pre-sets, and cleared in-memory state (plan §7.3). "Restart within test" (`RESTART`) is `restart()`; plan §7.3 gives the exact sequence (start as desktop startup does, `initChatControllerOnStart()`, `C/platform/Core.kt:59`, with `AppScreen()` composed at once so start-up alerts such as "Start chat?" can show).
   - Notices checked once at first composition (the SimpleX Lock notice, `C/App.kt:94-103`; the app-update notice, desktop `Main.kt:79-87`; What's New is catalogue 01's) are tested by clearing their pre-set pref, creating the conditions (more than 3 chats), and restarting (plan §11.1).
5. **Platform object.** `platform = object: PlatformInterface{…}` is set in `apps/multiplatform/desktop/src/jvmMain/kotlin/chat/simplex/desktop/Main.kt:65-90`. The harness installs an equivalent, or the update notice never shows.
6. **Servers.** Preset operators (SimpleX Chat, Flux) point to public servers, which are unreachable in the test network namespace (plan §8.3). The harness sends `/_servers <userId> [json]` (a JSON array, `Library/Commands.hs:6201`) with the preset operator groups disabled and one custom group with the local servers (plan §8.2).
   - "Your servers" is listed only when an operator-less server group exists (`NS/NetworkAndServers.kt:233-260`).
7. **Lock and window focus.** The lock uses the window focus listener (`DesktopApp.kt:184-206`), which doesn't fire in tests. Simulate it with `AppLock.appWasHidden()` and `AppLock.recheckAuthState()` (`C/AppLock.kt:271-290`).
8. **Desktop DB defaults.** A fresh desktop DB gets a random passphrase stored in settings: `InitialRandomDBPassphrase=true` (`C/views/helpers/DatabaseUtils.kt:51-71`). This blocks Export and Migrate until a passphrase is set.
