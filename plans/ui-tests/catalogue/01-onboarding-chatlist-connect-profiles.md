# UI test catalogue 1: onboarding, chat list, connecting, profiles, address, contact info

Rows follow `00-legend.md` (paths, row format, Needs codes, users and CLI output, ownership). Each row has the exact strings.xml labels, file:line, test names, the GUI and CLI checks with matching Haskell tests, and blockers. Totals: **312 test cases, none of them `@Ignore`**, in 15 sections (details in `## Count` at the end).

## Setup every test needs
1. **Compose the real root** (`App.kt` → `AppScreen`/`MainPage`) so that `AlertManager.shared`/`privacySensitive.showInView()` (`C/App.kt:242,255`) render alerts. Alerts are material `AlertDialog` popups and the menus are `DropdownMenu` popups; both can be found with `onAllNodes`. `DefaultDialog` (a separate AWT window, `D/views/helpers/DefaultDialog.desktop.kt:25`) is defined but never used, so it doesn't block anything.
2. **Pre-set prefs** for onboarded tests unless the test is about them (full list in plan §11.1; onboarding boots keep defaults). Three notices are checked once at first composition, so a test about one of them changes the pref and then calls `restart()`: `laNoticeShown` (the "SimpleX Lock" alert appears once there are more than 3 chats, `C/App.kt:94-103`), `appUpdateNoticeShown` (the app-update channel notice, `apps/multiplatform/desktop/src/jvmMain/kotlin/chat/simplex/desktop/Main.kt:79-87`) and `whatsNewVersion` (What's New, `ChatListView.kt:219-228`). The others take effect without a restart: `oneHandUICardShown`, `addressCreationCardShown`, `getStakeBannerDismissed` (crowdfunding is always available on desktop, `C/views/onboarding/WhatsNewView.kt:1073`), `supporterBannerShown` and `showHiddenProfilesNotice` are read through `.state` (`ChatListView.kt:950-955`, `UserProfilesView.kt:191`); `showMuteProfileAlert`, `showDeleteConversationNotice` and `showDeleteContactNotice` are read when the action runs (`UserProfilesView.kt:119`, `ChatInfoView.kt:259,337`); `privacyLinkPreviewsShowAlert` is read when a typed link is first detected (`ComposeView.kt:476`); `privacyDeliveryReceiptsSet` is read only in `startChat` (`SimpleXAPI.kt:679`; catalogue 04 owns its tests).
3. **Local servers only.** `acceptConditions` → `setServerOperators` (`C/views/onboarding/ChooseServerOperators.kt:293-311`) enables the operators selected during onboarding (`enabledOperators`, :331-358), whose preset servers are unreachable in the loopback namespace; onboarded tests get the local servers in `resetForTest`; onboarding tests call `TestServers.configure()` (`configureServers(smp1, xftp1)`) after the chat list appears and before anything connects (plan §8.3). No core change is needed.
4. **Async waits.** Most actions run through `withBGApi`; every lookup and assertion polls with the manual clock (plan §6). Known delays: the What's New modal waits 1 s (`ChatListView.kt:225`), name search is debounced 300 ms (`ChatListView.kt:1143`), and the subscription indicator polls every 1 s (`ChatListView.kt:686`).
5. **Controls with no text or contentDescription.** Tests find these by their `Ui` keys (plan §3):
   - unread filter toggle (`ChatListView.kt:758`, `NewChatSheet.kt:582`)
   - operator logo cards (`ChooseServerOperators.kt:234`)
   - copy/share icons in `LinkTextView` (`NewChatView.kt:751-762`)
   - toolbar call button (`ChatView.kt:1291`)
   - one-hand card close (`ChatListView.kt:168`)
   - user picker avatars
6. **Onboarding goes through the passphrase step.** A fresh database has a random passphrase (`initialRandomDBPassphrase`), so "Link a mobile" goes to "Setup database passphrase" first (`D/views/onboarding/SimpleXInfo.desktop.kt:19`), and "Create profile" goes there right after the profile is created (`C/views/WelcomeView.kt:400`). Tests reaching later steps pass it (e.g. "Use random passphrase").
7. **QR codes can't be read in the test.** Assert link text through the clipboard stub, or read `chatModel.showingInvitation`/`userAddress` directly.
8. **Context menus** open on right-click (`D/views/chatlist/ChatListNavLinkView.desktop.kt:39-41`): use the driver's `rightClick()` or `longClick()` (plan §7.4).
